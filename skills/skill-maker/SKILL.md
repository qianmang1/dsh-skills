# skill-maker

指导从需求到可交付技能包的完整流程，遵循本机技能惯例：frontmatter（name=目录名、description 含触发词）、正文四节（触发条件/步骤/自检/边界）；先用 ponytail 原则反过度设计，只造最小可用技能。

## 触发条件

- 用户要新建技能、把重复性流程封装成技能、改造或评审已有技能

## 步骤

1. **澄清需求**（缺信息先问，不猜）：技能名（kebab-case，≤3 段）、一句话用途、触发词、核心流程（要执行哪些命令/判断）、完成标准。
2. **查重**（不重复造）：检查 ~/.dsh/skills、~/.agents/skills、当前项目 .agents/skills 是否已有同职责技能；有则指引复用或改造，不新建。
3. **定安装位置**：
   - 通用（全部工作区）→ ~/.dsh/skills/<名>/SKILL.md（user-dsh 源）
   - 项目专属 → <项目根>/.agents/skills/<域>-<名>/SKILL.md（前缀用项目域名）
4. **写 SKILL.md**：
   - frontmatter：name = 目录名；description 一句话、含触发词、能有中文触发词（供 agent 判断何时调用）
   - 正文四节：## 触发条件 / ## 步骤（真实可执行命令，路径相对项目根或用 ~ 或 $env:USERPROFILE）/ ## 自检（可量化完成标准）/ ## 边界（何时不套用）
   - 不写"为什么要做"（归 .agents/notes/）；纯流程技能以清单自检，含命令/脚本的非平凡逻辑留一个最小可运行自检
5. **交付前自检清单**（逐项过）：
   - name == 目录名（kebab-case）
   - description 含触发词（Use when / 当用户 / 使用）且 ≥ 10 字
   - 四节齐全（触发条件/步骤/自检/边界）
   - 每条命令真实存在（实跑过或确认过）；无编造路径
   - 有自检与边界；无多余文件、无多余抽象（ponytail）
   - 若目标项目有 scripts/check.mjs，运行通过
6. **交付**：说明安装位置与一句用法；命令类技能给出实际运行证据。

## 自检

- 产出技能满足上述清单；含命令的步骤给出实际运行/验证结果
- 通用技能装在 ~/.dsh/skills/<名>/SKILL.md，frontmatter 可被 DSH 解析（可从技能目录加载）

## 边界

- 不编造命令/路径；流程不确定先列步骤问用户，不擅自扩大范围
- 不自动改写用户已有技能，改动先确认
- 一次性低价值流程不值得封技能；技能只服务于重复性、有判断门槛的流程
